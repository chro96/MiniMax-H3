# Local Studio レビュー記録

2026-10-10、`claude-call --model claude-opus-5-5` でコード・仕様・テストをレビュー。応答の `modelUsage` でも `claude-opus-5-5` を確認した。生成素材・認証情報は送信していない。

| 指摘 | 対応 |
|---|---|
| 秒数の型・精度で不一致になる | 保存時に整数フレームへ正規化。照合はフレーム数を使い、元の入力から既存ハッシュを移行。合成はカットのフレーム数を明示 |
| 撮り直し後の選択と重複生成 | テイクの採用は明示操作を維持。一致する完了テイクがあれば不一致生成の対象から除外。合成を省略した理由をジョブへ表示 |
| 一つの失敗でバッチが中止される | カットごとに失敗を記録し残りを処理。ジョブへ失敗カット番号を表示 |
| AI提案で未保存編集が失われる | 編集中は提案の確認・反映を拒否。保存後に新しい本文から再提案 |
| 終了時に受付済みIDや合成途中のファイルが残る | ID保存まで終了を待機。停止時にメディア子プロセスを終了・回収。排他ロック取得後に未登録の合成フォルダを整理 |
| ポーリングでプレビュー・履歴がリセットされる | 進捗はその場で更新。再描画時も同じ動画要素と履歴の展開を保持 |
| 音声の長さで映像の不足を見逃す | 映像ストリームの尺で検証 |
| ワーカーが例外で停止する | ループで例外を記録し、処理記録から回復して再試行 |
| コマ割り変更で旧テイクを画面から見られない | 現在のコマ割りから外れたテイクの再生・ダウンロード・プロンプト履歴を追加 |
| 漢字だけのセリフを日本語と推測する | 言語を明示指定可能にし、自動判別できない場合は推測しない |
| ライブラリのポーリングが表示へ反映されない | データが変わった場合に再描画し、検索の入力位置を保持 |
| 404メッセージの引用符・素材パスの正規表現 | メッセージ本文を使い、拡張子のドットをエスケープ |

追加の確認で見つけた保存中の入力消失も修正。非同期の更新・素材登録・移動を順番に処理し、古い画面の応答を破棄する。全体のAI構成提案では既存セリフもコード側で保持する。

同じOpus 5.5セッションの再レビューではP1なし、P2が1件（操作完了後に古いポーリング応答が表示を戻す）。操作カウンターとバージョンで応答を照合し、プロジェクト・ライブラリ双方の回帰テストを追加した。

最終確認でも同じOpus 5.5を使用し、残ったP2は解消済みとの回答を得た。操作開始前・実行中・完了後に届く応答をそれぞれ拒否できることをコードと回帰テストで確認した。

## Windows・既存ComfyUIへの接続

追加分も `claude-call --model claude-opus-5-5 --new-session minimax-windows-comfy-review` でレビューし、応答のmodelUsageを確認した。ユーザーのWindows / RTX 3060 12GB / RAM 32GB環境ではH3が動作済みとの報告があるため、既存ワークフローのモデル・解像度・推論設定を保持する接続方式を採用した。

初回レビューの12件をコードと一次資料で照合し、以下を対応した:

- Windowsレジストリに依存しないJS/CSS・動画のContent-Type、専用のHTTP権限・404例外、排他ソケット。
- Windowsのバイト範囲ロック、UTF-8 BOM / UTF-16設定ファイル、フォントパスとURL用の区切り文字。
- メディア子プロセスを独立したグループで起動し、停止を中断として記録。Ctrl+Breakと明示的な二度目の停止操作にも対応。
- ComfyUIの一時的な通信失敗へ上限付き再試行、HTTP 4xxの受付拒否とノード検証メッセージを表示。
- ComfyUIの設定誤りがあっても他の生成先・ライブラリを利用可能にし、設定画面へエラーを表示。
- Windowsの一時的なファイル使用中エラーへ短い再試行。ワークフローを置き換える前に履歴を保存し、画面から復元可能にした。再読込はユーザーの明示操作であり、追加の承認ダイアログは設けていない。
- 受付IDを入力ハッシュ付きの独立ファイルへ記録し、SQLite書込失敗後も同じ入力のIDだけを回復。両方の保存が失敗した場合もターミナルへIDを残す。
- 参照画像は一意な名前でComfyUI入力フォルダへアップロードし、カスタム画像ノードのトップレベル一覧にも対応。

公式ComfyUIのAutogrowが番号順に画像スロットを展開することも確認し、JSONのキー順に依存しない参照画像の割当へ修正した。

検証: Pythonの既存31件とComfyUI追加13件（計44件）、Nodeの13件。ComfyUIは模擬HTTPで投入・回収・一時失敗・受付拒否を検証し、実ffmpegで形式変換、30秒合成、部分撮り直し、旧完成版保持、承認を検証。起動中のローカルComfyUIへは読取専用の接続・H3ノード照合を行った。WindowsネイティブのStudio実行と、ユーザーの動作済みH3ワークフローからの実生成は、こちらでは未実施。

再レビューでは元の12件は解消し、終了時のシグナル処理・独立子プロセスの回収・動画ダウンロードの通信失敗にP2が3件残った。タイムアウト付きjoin、子プロセスの登録と停止、一意な試行用ファイル、使用中の合成フォルダの清掃延期、動画ダウンロードの最大5回再試行とContent-Length照合を追加した。回帰テストで子プロセスの終了、起動を妨げない清掃、HTTP 503と不完全ダウンロードからの回復を確認した。

同じOpus 5.5セッションで最終確認し、残ったA/B/Cは解消、P1/P2の指摘なしとの回答を得た。最終検証はPython 44件・Node 13件（計57件）成功。Pythonコンパイル・JS構文・差分の空白チェックも成功した。
