# MiniMax Local Studio

30秒の動画を「コマ割り → カット生成 → テイク選択 → 合成 → レビュー・保管」で制作するローカルアプリです。モデル配布用の既存ファイルに手を加えず、`studio/` に制作機能を追加しています。

## 起動

Python 3.10以降と `ffmpeg` / `ffprobe` が必要です。Studio自体はPython標準ライブラリだけで動作します。モデル推論の `requirements.txt` をStudioのためにインストールする必要はありません。

```bash
cd /Users/masa14inch/projects/companies/ip_makers_studio/miniMaxLocal
python3 -m studio
```

[http://127.0.0.1:8790](http://127.0.0.1:8790) を開きます。ポート・保存先を変更する場合:

```bash
python3 -m studio --port 8791 --data-dir data/my-studio
```

macOSで動画処理ツールが未導入なら `brew install ffmpeg`。Studioは127.0.0.1にバインドし、ローカルの制作画面として使用します。同じ保存先で二つのStudioを起動すると、ワーカーのロックで重複実行を防ぎます。

## 最初に試す

1. 「新規制作」でタイトルとアイデアを入力。標準は **5カット × 6秒**。6×5、3×10、2×15も選択できます。
2. 「サンプルを入力」で小さなロボットと花のコマ割りを入力するか、手動で各コマを編集します。
3. 「変更を保存」。「生成先」を **デモ** に切り替えます。
4. 「全カットを生成」から内容を確認して開始。色付きの検証映像を作り、全カットがそろうと30秒のMP4へ合成します。
5. 一つのカットの「動き」を変更して保存。そのカットのテイクが「本文と不一致」になります。
6. そのカットだけを再生成し、「テイク履歴」から新しいテイクを「合成に使う」で選択。
7. 「選択したテイクで合成」で完成版r2を作成。r1も完成版の履歴から再生・保存できます。

デモは操作とメディア処理の検証用です。ロボットなどのAI映像は描画しません。デモの完成版は承認できず、H3映像と混在して合成できません。

## H3で映像を生成

Studioは**既に起動しているSGLang H3サーバー**に接続します。Mac上で制作画面を動かし、別のGPUマシンで推論を動かす構成でも利用できます。Studio起動だけではモデルをダウンロードしたりGPUを確保したりしません。

```bash
cp .env.studio.example .env.studio
```

`.env.studio` に接続先を設定し、Studioを再起動します:

```dotenv
H3_BASE_URL=http://127.0.0.1:30010
H3_REF_BASE_URL=http://127.0.0.1:30011
H3_API_KEY=
H3_POLL_SECONDS=3
H3_TIMEOUT_SECONDS=3600
```

- `H3_BASE_URL`: `--model-variant fl2va` のサーバー。画像参照のないカットを `t2va` で生成します。
- `H3_REF_BASE_URL`: `--model-variant ref2va` のサーバー。キャラクター画像やコマの構図参照があるカットを `ref2va` で生成します。
- 画像は `conditions` のData URIとして送信するため、Studioと推論サーバーの間でファイルパスを共有する必要はありません。
- POST `/v1/videos` → GET `/v1/videos/{id}` → GET `/v1/videos/{id}/content` の非同期APIを利用します。

H3の1回の出力は4〜15秒です。Studioはカットに分割し、合計30秒の構成を生成・合成します。GPUの種類とメモリに合わせたサーバー起動方法は、[SGLang公式H3ガイド](https://docs.sglang.io/cookbook/diffusion/MiniMax/MiniMax-H3) とこのリポジトリの [ローカルデプロイ説明](../README.ja.md#h3-base-のローカルデプロイ) を参照してください。最初のバージョンの接続先はSGLangです。ip-short-makerのColab自動確保・停止処理は移植していません。

## アイデアからAIでコマ割り・部分修正

Chat Completions互換のテキストモデルを `.env.studio` で設定すると、AIコマ割りとAI部分修正を利用できます。ローカルモデルでも、対応する外部APIでも設定可能です。

```dotenv
STUDIO_LLM_BASE_URL=http://127.0.0.1:8000/v1
STUDIO_LLM_MODEL=your-text-model
STUDIO_LLM_API_KEY=
```

`STUDIO_LLM_BASE_URL` の後ろに `/chat/completions` を付けて呼びます。画面にはAPIキーを表示しません。設定済みのモデルへ、アイデア・キャラクター設定・コマの本文を送信します。画像そのものはテキストモデルへ送りません。

- **AIでコマ割り案**: 日本語のアイデアから、日本語のカット名・メモとH3向けの英語本文を提案。
- **AI修正案**: 修正指示を入力し、そのカットの本文だけを改稿。他のカット、秒数、参照画像を固定します。
- **提案を確認 → 本文に反映**: AIの変更をレビューしてから保存。反映だけでは映像を生成しません。
- 提案後に手動編集した場合、古い提案は反映できません。現在の本文から再提案してください。
- 未保存の編集がある間は提案の確認・反映を拒否します。全体のコマ割り提案は入力済みのセリフを保持します。セリフの言語をカットごとに指定でき、自動判定できない漢字だけのセリフは言語を推測しません。

AI未設定でも、空のコマ割り・サンプル・手動編集・JSON読込・生成・合成・管理を利用できます。日本語のメモ欄は制作管理用です。H3の実投入に使う映像・動き・カメラなどの欄は英語で記入し、セリフだけは話す言語のまま指定します。

## テイクと完成版の扱い

| 操作 | 結果 |
|---|---|
| 本文を保存 | 本文だけを保存。映像を生成しない |
| この本文で再生成 / 撮り直し | 指定カットの新しいテイクを作る。既存の使用テイクは維持 |
| 合成に使う | 使用するテイクの選択だけを保存。完成版は維持 |
| 選択したテイクで合成 | 現在の選択で新しい完成版を作る。過去の完成版も保持 |
| BGM・元音声の消去を変更 | 生成済み映像を再利用して合成。新しいAI動画生成を行わない |
| 完成版を承認 | 現在の本文と構成に一致するH3完成版を確定。編集をロック |
| 編集へ戻す | 承認を解除して修正可能にする。完成版と履歴は保持 |
| アーカイブ / 復元 | 通常表示から外す / 戻す。データは削除しない |

各テイクに、生成時の本文・全体設定・実投入プロンプト・seed・生成先・H3ジョブIDを保存します。現在の本文から組み立てた入力と照合し、一致・不一致を表示します。日本語のメモと音声消去など合成だけの設定は、動画再生成の不一致判定に含めません。

カットの終端状態は次のカットのプロンプトに入ります。その終端を直すと次のカットも不一致になります。全体の画風・キャラクター・世界観などを直すと全カットが不一致になります。これはテキストによる連続性の指定であり、前の生成動画の最終フレームを自動投入する機能ではありません。

合成は不一致テイク、未完了テイク、デモとH3の混在を拒否します。合成完了まで現在の完成版を保持します。

「不一致・未生成だけ生成」は、選択中でなくても現在の本文に一致する完了テイクが生成先にあれば再投入しません。そのテイクを履歴から選択してください。JSON読込でコマ割りから外れたテイクも、画面下部の履歴から再生・保存できます。

## 合成・保存形式

- H.264 MP4、24fps、720フレーム、30秒。H3完成版は短辺768pxに正規化。
- 秒数は保存時に整数フレームへ正規化し、6と6.0などの表記差では再生成を要求しません。既存テイクの照合ハッシュは起動時に元の生成入力から移行します。
- 映像の比率を維持してフィットし、必要なら余白を追加。カットごとにfpsと音声をそろえます。
- H3の尺の量子化で不足した0.5秒以内は最終フレームを保持。0.5秒を超える不足はエラーにします。
- 元音声なし・消去指定のカットには無音を追加。BGMを全編へ重ね、終端1秒でフェードアウト。
- 完成版の `manifest.json` には、各カットのテイクID・revision・尺・音声設定・動画ハッシュと、合成時のコマ割りを保存。
- 「MP4を保存」で完成動画、「構成記録」でmanifest、「制作データを書き出す」でコマ割り・テイク・完成版の来歴をJSONで保存できます。

```text
data/studio/
  studio.sqlite3             プロジェクト・ジョブ・テイク・構成の正本
  worker.lock                同じ保存先のワーカー重複起動を防止
  assets/<id>.*              参照画像・BGM
  takes/<id>/raw.mp4         各テイクの映像
  takes/<id>/thumb.jpg       代表フレーム
  renders/<id>/master.mp4    完成版ごとのMP4
  renders/<id>/cover.jpg     完成版の代表フレーム
  renders/<id>/manifest.json 完成版の構成記録
```

`data/` と `.env.studio` はGit管理対象外です。バックアップするときはStudioを停止し、保存先ディレクトリをまとめてコピーしてください。JSON書き出しは素材ファイルを内包しません。

## ジョブの中断・失敗

- 一つのワーカーで順番に生成・合成します。処理中の同プロジェクトの編集・再投入・状態変更を拒否します。
- Studio停止時にH3の受付済みジョブIDを保存。再起動すると同じIDの状態確認・回収を続けます。新規POSTは行いません。
- 待機のタイムアウトや回収失敗時には、テイク履歴の「同じジョブを回収」で追加生成せず結果を再取得できます。
- POSTの受付後、ジョブID保存前に異常終了した場合は受付結果が不明です。自動再投入せず失敗を記録します。H3サーバー側のジョブ一覧を確認してください。
- 部分失敗でも先に完了したテイクは保存します。失敗・未生成カットを再生成して続行できます。
- 一つのカットが失敗しても残りのカットを処理し、失敗したカット番号をジョブへ記録します。撮り直し後に使用テイクの選択が必要な場合、処理履歴へ表示します。
- 通常の終了操作ではH3受付処理とジョブID保存の完了を待ちます。実行中のffmpegは終了・回収し、合成途中の未登録ディレクトリは次回起動時に整理します。
- Studioを停止してもH3サーバーの推論やGPUそのものは停止しません。サーバーの稼働管理は別途行ってください。

## コマ割りJSONの読込

「JSONからコマ割りを読み込む」で、document単体またはStudioの制作データ書き出しJSONから本文を読み込めます。合計30秒、2〜7カット、各4〜15秒を検証します。秒数は1/24秒単位です。

カットIDは32文字の小文字16進数。省略すれば新しいIDを付けます。既存カットのIDを保持するとテイク履歴との対応も維持されます。画像・BGMのIDは読み込むプロジェクトの保存済み素材を指定する必要があります。他プロジェクトから本文だけを持ち込む場合は `character_reference` / `bgm` をnull、`references` を空配列にしてから、画面で素材を登録してください。

## 検証

```bash
python3 -m unittest discover -s tests -p 'test_studio.py' -v
node --check studio/static/app.js
node --test tests/test_studio_ui.cjs
```

テストは一時保存先と模擬H3サーバーを使います。外部APIやGPUを利用せず、実際のffmpegで30秒MP4・BGM・部分再生成・過去原盤保持を検証します。H3実機の映像品質や推論性能は、接続先のGPU環境で別途確認が必要です。

画面側の回帰テストはNode標準のテストランナーを使い、保存中の編集保持、古い画面応答の破棄、AI提案による編集消失の防止、重複生成の回避、進捗更新とライブラリの再描画を検証します。
